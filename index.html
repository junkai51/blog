    追了一圈各种小龙虾XXClaw，答案却藏在ChatGPT侧边栏：OpenAI Codex终于做好了“AI用电脑”这件事

    过去几个月，我像追连续剧一样追各种“xxClaw”“小龙虾”。 OpenClaw、CoPaw、QClaw、QoderWork、WorkBuddy……名字一个比一个像能从桌面角落里爬出来帮我打工。最开始体验OpenClaw时最兴奋，那是过年那会儿，我把 OpenClaw 接上钉钉，然后用手机给它发消息，让它在实验机上整理文件、处理桌面任务。 在当时，那个瞬间确实很有未来感。 人在海滩上打扑克，电脑在城市的另一边，AI 在那里默默操作文件。以前说“AI 使用电脑”总觉得像 demo，直到我真的在手机上发一句话，回头看到实验机上的任务做完了，才觉得这东西离现实不远。 但也是那一周，我开始对 OpenClaw 这类桌面智能体冷静下来。 它方向很有前景，但问题也暴露得很清楚：权限怎么给？成本怎么控？它凭什么碰我的文件、浏览器、账号、密钥？出了错谁负责？一个普通用户到底应该把多少电脑交给它？ 当时我写 OpenClaw 的结论，大概是：它不是答案，但它让答案变得可见。 结果兜兜转转几个月之后才发现，这个“答案”不是我追着看的各种小龙虾换壳版，而是曾经藏在 ChatGPT 侧边栏里很不起眼的 Codex。 更准确地说，是最近几个月更新之后的 Codex App。 Codex 一开始压根儿不是干这个的 Codex 并不是新东西。 2025 年 5 月，OpenAI 发布 Codex，当时官方描述是一个 cloud-based software engineering agent。它可以在 ChatGPT 侧边栏里接收编码任务，跑在独立云沙箱里，读写代码文件，运行测试、linter、type checker，然后把结果提交给你审查。 那时候我对它的感受差不多是：“哦，ChatGPT 里面多了个能帮忙改代码的远程工位，不过我写代码有 cursor 啊，用不着这个。”那时日子就这么惬意，除了新模型好像就没什么能在科技圈掀起波澜的。 能让我感到兴奋的是 25 年底横空出世的 OpenClaw 这样更刺激的东西：能操作桌面，能接聊天平台，能像一个系统用户一样去完成任务。虽然粗糙，但有一种很强的冲击力。 所以后来我追 OpenClaw，追腾讯的 WorkBuddy/QClaw，甚至研究豆包手机、Galaxy AI、AppFunctions 这些路线时，也完全没有把 Codex 当成同一张桌子上的玩家。不过倒是用上了 Codex：此时大家都开始脱离 IDE 使用 Claude Code 这样的命令行 AI 工具来写代码，而我那时也想赶潮流，却还不太会用命令行，既有 CLI 端又有桌面端 App 的 Codex 便被我作为 Claude Code 的替代品。 ...

    两次烧光 Codex 额度，我意识到做成一个项目没那么简单

    我依然在改那个扑克筹码工具，本来只是想要让它变得能用，现在尝到了些 AI coding 的正反馈，就不愿停下来，想要一鼓作气把它做成一个真正拿得上台面的“项目”——“无非就是把功能做得更完整，把安全性搞好点，收个口，写些文档而已，应该不会有多麻烦吧！”我天真地认为。毕竟我已经闲到开始做彩蛋了。 先聊点开心的好了——令我相当满意的“彩蛋” 我对筹码的一个小执念，就是要在牌桌上做叠筹码的小动作，感觉很帅很好玩 （其实很吵很傻帽），这也是我喜欢德扑的一点。这个动作叫 Chip riffle，暂且译作“筹码叠洗”。有些线上扑克游戏把这做成了可发送的表情用来交流、搞心态，但我更希望把这个做成有互动性、就好像自己上手去叠一样的小游戏。 我向 codex 讲清了要做什么，包括一张张穿插叠起的过程，分成两堆又叠回一堆的循环，从下往上堆起，下面的筹码堆叠时上面的会被垫高、倾斜等细节。最后敲定了一套通过点按与滑动触发筹码动画的方案，还加了声效、多种配色，又让筹码能定位而非循环放动画（若用双色筹码可以观察到堆叠时筹码被打乱又逐渐恢复）。 中间走了些弯路，尤其是音效的问题，我原本使用 web audio 来生成音效，但怎么调都不对味，还始终不能消除掉我的手机上测试时发出的“爆鸣声”。最终选择全部推倒，换成真实音效，没想到开放使用的声音资源还挺多，而且质量非常好。配合上用 web audio 搓音效时形成的逐渐拉高音高来制造“爽感”的经验，最终的效果非常好。 这个功能与本体没有什么关系，但我觉得这能让这个工具显得更有活力，而且确实挺好玩。 小改 UI 不如重构逻辑，但麻烦也由此开始 在此之前，玩家信息是用卡片状的 box 显示的，在大屏端横向排列，手机端锁定一行一个。我的构想是一个玩家只需要在自己的设备上注意自己的卡片，所以这样处理会很方便、优雅。然而，实际游玩时，我发现玩家会需要连续上下翻找查看轮到谁操作、上个人下了多少等信息的，而手机端巨大的卡片反而成了负担。 我首先想到的是把卡片缩小、让屏幕里能放下更多，顺便把跟注数额显示出来而不需要去找上个行动的玩家，发现当前未轮到操作的玩家仍然保留不可点按的操作按钮是很占地方的，于是把按钮去掉，把当前操作玩家外的玩家卡片缩成较小的条状卡片，而大屏端保持原本状态。然后……都这样了，不如直接把操作按钮提取到一个固定位置，而玩家卡片部分只显示信息。 但我发现这样反而不太对劲，因为下面的玩家卡片不再有什么变化，就让网页有了一种不可明状的廉价感。我想要的德州扑克筹码管理工具应该是什么样呢？我头脑中浮现出一个椭圆形的牌桌，玩家围坐在牌桌周围，按顺时针行动——这才像样嘛，当然这也不是我自己想出来的，而是那些线上扑克游戏都长这样，最开始用 copilot 构建的时候实在想不到该怎么实现才没有采用，现在既然已经将操作控制和信息显示分离，玩家卡片可以压缩得更小，采用椭圆形牌桌，大屏端横向排布，手机端纵向排布，效果应当是很好的。 Codex 对这些有关图形的需求理解也很到位，两次调整就做出了我想要的“较方的椭圆形牌桌”，并且把玩家卡片缩小成了仅包含玩家名、筹码数、下注信息、位置信息的小胶囊，可通过点击来展开浮窗查看详细信息，又把底池、轮次等信息迁移到牌桌中央，计划后面把操作按钮也放在中央……感觉改对了方向，工具的档次将要再提升一截！然而，当我要把玩家卡片放在桌子的合适位置上时，却几乎回到了那个与 copilot 拉扯的燥热夏天。 玩家排布总是改不合理：不对称、过于拥挤、相互遮挡、挡住中心信息……Codex 开始不总能理解我的要求，我想也许也跟我为了省用量不让用 playwright 自己跑结果有点关系。最后连着改了几组对话，还是不满意，于是我让 codex 直接告诉我在哪改数值，我去手动一个个把排布改到合理的状态，对总共九种（2-10名玩家）排布…… 至少算是搞定了，看到界面如此完善，我决定再改得人性化一些——加入了包括本工具使用说明、德州扑克游戏规则、牌型大小速查表的玩家手册，还有 github 页面、作者信息的页尾标注，然后就兴奋地去找同学、朋友、家人去打牌测试了。 问题只有真正使用时才能显现出来 真正打起牌来，和没有与我一起开发，没有忽略我想当然的事项，甚至不太熟悉扑克规则的“用户”们，暴露出来了许多问题。 圆形排列对于上方的玩家很不友好，因为对他们左右是反的，难与现实牌桌上的人对上； 所有操作都在一个位置，搭配上网络同步有点延迟，很容易想点自己的操作却点了别人的； 我与家人打牌一般打光一个人就停了，但程序不能到这就出错，需要调整位置分配，确保剩下的人还能玩，甚至让打光的人能补码回来； 大家用的乱七八糟浏览器远没有 Chrome 贴心
