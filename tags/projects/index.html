    两次烧光 Codex 额度，我意识到做成一个项目没那么简单

    我依然在改那个扑克筹码工具，本来只是想要让它变得能用，现在尝到了些 AI coding 的正反馈，就不愿停下来，想要一鼓作气把它做成一个真正拿得上台面的“项目”——“无非就是把功能做得更完整，把安全性搞好点，收个口，写些文档而已，应该不会有多麻烦吧！”我天真地认为。毕竟我已经闲到开始做彩蛋了。 先聊点开心的好了——令我相当满意的“彩蛋” 我对筹码的一个小执念，就是要在牌桌上做叠筹码的小动作，感觉很帅很好玩 （其实很吵很傻帽），这也是我喜欢德扑的一点。这个动作叫 Chip riffle，暂且译作“筹码叠洗”。有些线上扑克游戏把这做成了可发送的表情用来交流、搞心态，但我更希望把这个做成有互动性、就好像自己上手去叠一样的小游戏。 我向 codex 讲清了要做什么，包括一张张穿插叠起的过程，分成两堆又叠回一堆的循环，从下往上堆起，下面的筹码堆叠时上面的会被垫高、倾斜等细节。最后敲定了一套通过点按与滑动触发筹码动画的方案，还加了声效、多种配色，又让筹码能定位而非循环放动画（若用双色筹码可以观察到堆叠时筹码被打乱又逐渐恢复）。 中间走了些弯路，尤其是音效的问题，我原本使用 web audio 来生成音效，但怎么调都不对味，还始终不能消除掉我的手机上测试时发出的“爆鸣声”。最终选择全部推倒，换成真实音效，没想到开放使用的声音资源还挺多，而且质量非常好。配合上用 web audio 搓音效时形成的逐渐拉高音高来制造“爽感”的经验，最终的效果非常好。 这个功能与本体没有什么关系，但我觉得这能让这个工具显得更有活力，而且确实挺好玩。 小改 UI 不如重构逻辑，但麻烦也由此开始 在此之前，玩家信息是用卡片状的 box 显示的，在大屏端横向排列，手机端锁定一行一个。我的构想是一个玩家只需要在自己的设备上注意自己的卡片，所以这样处理会很方便、优雅。然而，实际游玩时，我发现玩家会需要连续上下翻找查看轮到谁操作、上个人下了多少等信息的，而手机端巨大的卡片反而成了负担。 我首先想到的是把卡片缩小、让屏幕里能放下更多，顺便把跟注数额显示出来而不需要去找上个行动的玩家，发现当前未轮到操作的玩家仍然保留不可点按的操作按钮是很占地方的，于是把按钮去掉，把当前操作玩家外的玩家卡片缩成较小的条状卡片，而大屏端保持原本状态。然后……都这样了，不如直接把操作按钮提取到一个固定位置，而玩家卡片部分只显示信息。 但我发现这样反而不太对劲，因为下面的玩家卡片不再有什么变化，就让网页有了一种不可明状的廉价感。我想要的德州扑克筹码管理工具应该是什么样呢？我头脑中浮现出一个椭圆形的牌桌，玩家围坐在牌桌周围，按顺时针行动——这才像样嘛，当然这也不是我自己想出来的，而是那些线上扑克游戏都长这样，最开始用 copilot 构建的时候实在想不到该怎么实现才没有采用，现在既然已经将操作控制和信息显示分离，玩家卡片可以压缩得更小，采用椭圆形牌桌，大屏端横向排布，手机端纵向排布，效果应当是很好的。 Codex 对这些有关图形的需求理解也很到位，两次调整就做出了我想要的“较方的椭圆形牌桌”，并且把玩家卡片缩小成了仅包含玩家名、筹码数、下注信息、位置信息的小胶囊，可通过点击来展开浮窗查看详细信息，又把底池、轮次等信息迁移到牌桌中央，计划后面把操作按钮也放在中央……感觉改对了方向，工具的档次将要再提升一截！然而，当我要把玩家卡片放在桌子的合适位置上时，却几乎回到了那个与 copilot 拉扯的燥热夏天。 玩家排布总是改不合理：不对称、过于拥挤、相互遮挡、挡住中心信息……Codex 开始不总能理解我的要求，我想也许也跟我为了省用量不让用 playwright 自己跑结果有点关系。最后连着改了几组对话，还是不满意，于是我让 codex 直接告诉我在哪改数值，我去手动一个个把排布改到合理的状态，对总共九种（2-10名玩家）排布…… 至少算是搞定了，看到界面如此完善，我决定再改得人性化一些——加入了包括本工具使用说明、德州扑克游戏规则、牌型大小速查表的玩家手册，还有 github 页面、作者信息的页尾标注，然后就兴奋地去找同学、朋友、家人去打牌测试了。 问题只有真正使用时才能显现出来 真正打起牌来，和没有与我一起开发，没有忽略我想当然的事项，甚至不太熟悉扑克规则的“用户”们，暴露出来了许多问题。 圆形排列对于上方的玩家很不友好，因为对他们左右是反的，难与现实牌桌上的人对上； 所有操作都在一个位置，搭配上网络同步有点延迟，很容易想点自己的操作却点了别人的； 我与家人打牌一般打光一个人就停了，但程序不能到这就出错，需要调整位置分配，确保剩下的人还能玩，甚至让打光的人能补码回来； 大家用的乱七八糟浏览器远没有 Chrome 贴心 还有许多小问题，这次不能再一个个问题去糊，而应该找找问题的共性，得到更有效的解法。 首先优化 UI，浏览器对弹窗一般都不太友好，会认定为骚扰信息，给出屏蔽选项甚至自动屏蔽，或是吞掉取消键改为直接退出网页 （也搞不懂是什么逻辑），我将所用用到 confirm 和 alert 的弹窗改为了自定义的浮窗，便解决了这个问题，还做了玩家卡片字体调整、中文名词推敲、添加快捷加注窗口不再必须手动输入 *（手机浏览器里调输入键盘又是一个很破坏体验的事情）*等等小修改。 但真正的问题不在这里，多人游戏中的混乱，不是改点 UI 就能搞定的，我必须要面对一直在逃避的玩家身份系统了。 玩家身份 + 房间系统 误触、视角、筹码数和位置管理、中途离桌、回桌、加减玩家……这些问题当然都可以一个个用小补丁糊好，但每个问题都好像在提醒我应该重新设计一个更合理的房间系统，区分出不同设备所控制的玩家。 我首先添加了一个牌桌管理界面，让两局游戏中途可以打开它来编辑玩家信息、修改筹码数、添加/删除玩家、调整座次，然后完善了打光离桌、补码回桌的规则。接下来继续利用这个牌桌管理界面，我开始做玩家身份系统——先不用复杂的注册登录，还是以房间为核心，但让创建房间的这一端作为房主，来批准其他加入房间的用户去绑定玩家。玩家绑定完成后再开始游戏，每个设备上对应的玩家就坐在那一端界面的牌桌底。接下来封死权限，让每端只能点击其绑定的玩家的操作，再留出换设备、换浏览器重连后接管玩家的功能。 再做一些小优化，让正在行动的玩家卡片有明显的动态高光提示，同时正在等待的其他端不再显示点不动的按钮，而是改成动态的“…等待某某行动”状态，再顺便给庄家做每条街发牌的提醒和其他玩家等待的 UI （太有必要了，想不起来发牌的庄家们），最后把确认赢家和开始下一局做成需要房间中所有人确认才生效，尽可能避免出错。 ...

    修复德州扑克筹码计数工具

    牌瘾依然很大，让我忽然想起十个月前，零前端基础的我用 github copilot 糊出来的那个德州扑克筹码计数器。那玩意的问题依然很大，用起来挺不方便，导致我不好意思让别人用，错过很多玩牌的好机会。 原来才过去不到一年呐，我和 AI 的进步看来都蛮快的。不如把这玩意改进一下，做到一个真正能用的状态，跟人玩牌就方便多了，还能作为我“作品集”的一员。 做了这么多测试、牛刀杀鸡、半途而废的小东西之后，也该用 codex 做些至少对我来说意义大一些的工作了。 Getting on the same page 作为早期的ai编程产物，这个项目的代码应当已经在当初改 bug 时堆成了一大坨，我目前也并没有掌握 javascript，自己看不太明白，甚至也记不住有什么 bug 要改了。于是打开 codex 后，先说了： 请给我讲讲这个项目 Codex 很机灵地讲了这个玩意的文件结构、工作方式、亮点、缺点，我就告诉它我觉得代码逻辑、安全性、健壮性等有不少问题，请它帮我检查，给出修改建议。 它一下列出了许多问题，以卡片方式排列，可以看出重要程度、问题简述和详细信息，选择忽略、前往代码。我就开启最高智能等级、高速模式、高权限，直接让它全部解决，又补充让它把之前简陋的手动输入赢家改为按钮选择。 出乎我的意料，这条命令的用量非常的大。它啃哧吭哧干了十几分钟，修好了全部它检查出的错误和安全隐患，改了上千行代码，又开始调 playwright mcp 去大量测试，直接用掉了 80% 的五小时额度。 我先赶紧把速度调回标准。去自己再进行测试。 巧妙或曲折，问题被一个个解决 All in 与边池 之前一直困扰我的一个问题是 all in 与边池规则，我其实自己都没有想明白要怎么解决——当有玩家筹码不足，进入全下的状态后，若其他玩家继续下注，就形成了边池，若全下的玩家胜利，只能赢走与他对等的筹码，而边池将会留给剩下的玩家争夺。听起来就很绕，我也没跟 LLM 讲明白过，且不知道该怎样高效测试，所以一直做不好。这次我要求把手动输入赢家改为按钮选择倒是歪打正着，codex 随手设计了一个用起来相当直观的底池系统—— 用按钮选择赢家，再按键确定，于是按钮能处于一个待选的状态，避免了误触、允许了多选平分，整体界面也很美观；all in 造成的边池往下排列，排除掉不可选的玩家即可，相当直观。 在同一个项目上工作，早期的 LLM + IDE 与现在的 coding agent 的对比就相当明显了，Agent 能够不断反问自己，使模糊的想法在思考中扩充成实现，考虑到许多细节，反复验证，确保成功运行 小修小补，以及每次都要卡我一下的，Git 当然也还会有点小问题。可能是记录状态的变量串了，导致弃牌也会被当作开边池的条件。我将这个问题返回给它，顺便让它把牌局记录做成可折叠的盒子，不要把页面越拉越长搞得不美观，另外让它少用用 playwright，太败家了，改完测好就同步到远程仓库去。 这次偷懒让我有了段奇妙的经历.因为没改到 main branch 上，这次的 commit 需要我再手动融合，然后打开 page 一看，结果竟是修改前和修改后的混合态——有一些明显是刚刚加的功能，但诸如选择赢家等功能却还是旧的方式。 codex 冷静解答： ...
